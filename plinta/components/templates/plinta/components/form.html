{% comment %} The form's shell, which is the component's and never a layout's. The record, the submit and the status live here. A layout that owned them could get one subtly wrong — the record's field, the action, the attribute Unpoly submits by — and the form would render perfectly and silently never save. A layout arranges controls; it cannot break saving. A real form post. Unpoly submits it in place and swaps in what comes back: the same form, drawn again with what was wrong beside each field, or saying it saved. `up-validate` asks the server the same question as each field is left, without saving; `up-disable` holds the controls while an answer is on its way. The CSRF token travels as a header the client configured, since this template is drawn without a request. {% endcomment %}
